# 检查清单

按本轮所处阶段选用对应部分。

# 阶段一：设定图

## 视图与姿态

- 交付四个独立文件，方向为用户要求的组合；正后左右不被俯视替代。
- 左右按角色自身定义，左视角色前方朝画面左，右视朝画面右。
- 没有明显透视、三分之四视角、俯仰、头身倾斜或T-pose与A-pose混用。
- 同一模块关键相对高度一致，完整轮廓不裁切；窄侧视不额外放大。
- 侧视遮挡合理，不为显示两条腿或双手而人为错开部件。

## 模块与接口

- 模块不夹带头部、人台、其他身体部件或未分配的尾巴。
- 刘海与后发共用同一冠状切面、冠顶、空腔宽度、壁厚和太阳穴端点。
- 裸头与头发空腔比例合理；短颈与围巾领口、大腿与裙摆、手腕与袖口关系明确。
- 不同模块独立放大后，通过整角色比例与接口标记比较，不能按图像总高拼接。

## 外观与局部细节

- 头发保留轮廓与流向；发块宽厚、浅槽、圆钝末端，没有深缝、细丝或新增发束。
- 兽耳、发夹和围巾归属正确；左右装饰不被镜像复制。
- 眼白没有灰带、眼窝暗缝或悬浮眼片；原虹膜高光仍保留且随侧视缩短。
- 手部五指逻辑正确，腕与袖口自然相接；严格侧视看到指尖，不是竖起手掌或握拳。
- 袜口、膝部、鞋口、鞋底对应；后视呈鞋跟，不复制鞋舌与脚背搭带。

## 输出记录

- 背景、画幅、实际原生与导出像素可核实；放大图片不标成原生高分辨率。
- 新版独立保存，最终清单不混入已弃用版本。
- 提示词区分设计参考、编辑底图与接口基准；一次只修明确问题。
- 多图生成存在细微误差时如实说明，不宣称严格共用几何或实际零穿模。

# 阶段二：UV 重排与贴图

数字取自 `output/metrics.json` 和 `report.md`。括号里是示例角色的实测值，作参考，不是硬门槛。

## UV 硬指标（必须满足）

- 越界、翻转、岛间重叠都是 0；运行时没有打印 `UV GATE FAILED`。
- 4K 图上最小岛间距不小于 16 像素（示例 20–21 像素）。
- 导出回读：
  - `preservation` 全部为 True：顶点、面、原 UV、权重、自定义法线都没变；
  - 重新打开 blend 后 `UV_clean` 逐值一致；
  - FBX 三角面数等于预期，第 0 通道等于 `UV_clean`；
  - 未绑定顶点 0，贴图 `n/n` 都能找到（示例 256030 面、64 骨骼、5 材质、5/5 贴图）。

## 排布（看 UV_Atlas_Overview 和 Region_ID_Sheet）

- 一个部位一整块面板；被自动二分的部位最多 2–4 块，编号相同。
- 左右件并排；主要面板头朝上、腿竖直、发根在上；同组部位连成一片，小件靠近所属部位。
- 缝线在背面、内侧或遮挡处；正面看得到的大面上没有缝。
- 利用率：
  - 目标不低于 65%（示例：头 75%、衣服 68%、腿 67%、后发 62%、刘海 53%）；
  - 细长头发件多的图集偏低属于正常，报告里要说明原因，不要为了利用率拆碎主面板。
- 共形畸变 P95（面积加权）：可见部件不超过 2（示例 1.4–1.8）；超过 2 的部件逐个说明。
- 岛数相比原始 UV 大幅减少（示例 13087 → 186）。

## 贴图

- 迁移保真：平均绝对差在 0.003 以下，差值大于 0.1 的面积占比在 0.1% 以下（示例 0.0007–0.0026、≤0.02%）。偏大时先查 `source_uv` 和原贴图。
- 图像模型清理：
  - 每块贴回后剪影重合度在 0.98 以上（示例 0.991–0.999）；
  - `islands_kept_original` 里列出的岛逐个确认是有意保留的；
  - 接缝找平后颜色差约 0.001 以下（示例 0.07–0.10 → 0.0003–0.0007）；
  - 脸和眼睛没有被改动，除非用户要求。
- 定点修正：用户指出的每个问题都对应一条 `touchup`，并在特写里确认已经修好。
- 特写（`Closeup_texture_cleanup.png` 加上背面、接缝的局部近景）里没有以下问题：
  - 岛边白边或旧色边；
  - 克隆补丁的台阶、切换线、“獠牙”楔形；
  - 相邻岛之间的色差；
  - 边线（袜口、袖口）在接缝处错位或有亮点。
- 清理前的迁移贴图（`work/transfer/*_migrated.png`）保留着，可以随时换回。

## 交付

- 交付文件夹结构完整：01_Model、02_Textures、03_UV_Guides、04_Preview、05_Validation、README、验收报告。
- 打包后的 blend 重新打开，贴图仍能从 `02_Textures` 相对路径找到（`package_readback.json` 的 `blend_reopen`）。
- 向用户如实说明未达标项和残留问题。例如“贴得很近才看得到的 2–3 mm 接缝折角”。

# 阶段三：UE 实机

- `build_report.json` 状态为 PASSED，并且：
  - 目标 IK Rig 的链条（Spine、Neck、Head、左右 Clavicle/Arm/Leg）完整；
  - 重定向姿势只在手臂上有偏移，脚和腿的偏移是 0°；
  - 脚部 IK 节点已换成直通 Control Rig。
- `verify_report.json` 状态为 PASSED，`checks` 全部为 True：
  - 待机时手低于上臂，脚平、脚尖向前；
  - 跑速大于 100；跑动时两腿交替；
  - 起跳时处于下落状态，之后落回待机。
- `UE_Playtest_Sheet.png` 里贴图正确，不是 T-pose，脚没有竖起来，头发和衣服没有明显穿出。截图是 PIE 实拍，不是编辑器摆拍。
- 项目全局设置没有改动；模板内容只在缺失时才复制，没有覆盖用户已有资产。
- 向用户说明限制：没有手指骨骼时手指不动；次级骨骼（头发、裙子）没有物理；脚部 IK 已关闭；材质还不是卡通着色。
