# 模块化角色工作流

同一个角色从设定图走到可玩的引擎角色，各阶段之间继承身份、模块归属和接口约定。

| 阶段 | 输入 | 产出 | 参考与工具 |
|---|---|---|---|
| 一 设定图 | 角色设定图、已确认的模块参考 | 每个模块的正交四视图 PNG、提示词、接口说明 | [prompts.md](references/prompts.md)、[quality-checks.md](references/quality-checks.md) |
| 二 UV 与贴图 | 按模块拆好的 .blend（AI 生成的网格、原 UV、原贴图，最好已绑骨） | 按部位重排的 UV、迁移并清理后的贴图、Blender/FBX/glTF 交付包、验收报告 | [uv-relayout.md](references/uv-relayout.md)、[texture-processing.md](references/texture-processing.md)、`scripts/origami_uv/` |
| 三 UE 实机 | 第二阶段交付包里带骨骼的 FBX 和贴图、UE5 项目 | 可直接 Play 的角色、关卡和 GameMode，实机测试截图 | [ue-playable-character.md](references/ue-playable-character.md)、`scripts/ue_character/` |

第一阶段和第二阶段之间的 AI 生成三维模型、组装和绑骨不在本技能范围内。没有骨架时第二阶段仍可用（导出静态网格），第三阶段必须有骨架。

## 确定本轮阶段与范围

- 按请求和已有文件判断本轮在哪个阶段：
  - 只有设定图、要出视图 → 阶段一；
  - 拿到模型，抱怨 UV 碎、贴图脏或有锯齿 → 阶段二；
  - 要进引擎、要能操控 → 阶段三。
- 只做用户要求的阶段。用户如需扩展到其他阶段，另按新请求开始，不由本技能自动扩展工作。
- 读取 [references/project-spec.md](references/project-spec.md) 建立项目约定，把新信息记进项目的 character-spec、config.yaml 或 ue_config.json。新角色不要自动套用示例的兽耳、鱼形发夹、格纹围巾、比例、部位名或分区规则。
- 缺少会影响归属、接口或输出的重要信息时才询问，其余继承已确认约定。

## 阶段一：设定图

本阶段仅制作、修复和整理设定图，不执行模型组装、绑骨或游戏资产处理。从会话与已有图像提取角色风格、姿态、视角顺序、配色、左右装饰、拆分定义和交付格式。范围外的尾巴与饰品记录为未分配，不擅自生成。

### 生成设定图

按需读取 [references/prompts.md](references/prompts.md)，只取本轮模块、方向语句和相关修复段。该文件的具体外观来自示例角色，先换成当前角色描述。

1. 锁定整角色正视基准或已有确认参考，记录头身比例及冠顶、眼线、肩、袖口、裙摆、袜口和鞋底的相对位置。
2. 一个模块先生成正视并检查，再以其为几何基准生成后、左、右视。每次生成一张图，四视图交付四个独立文件。
3. 标明每张输入图的作用：身份设计参考、待编辑底图、接口基准或已确认模块。其他部件只控制接口，不出现在独立模块成图中。
4. 保持物体坐标、姿态和尺度，仅改变观察方向。左右按角色自身定义；不要让所有视图都正面朝镜头。
5. 图像生成与内容修复使用当前环境可用的imagegen能力；有imagegen技能时遵循其工具约定，不用绘图代码替代生成式内容修复。
6. 检查后以局部编辑修一个明确问题，锁定其余设计。对称几何可参考对侧，不对称配件不能简单镜像复制。

### 接口与外观约定

- 采用前后180°头发拆分时，使用头部中心的竖直冠状平面，平行于正视图平面。不是水平切顶或额头发际线。刘海与后发共用冠顶、空腔宽度、壁厚和太阳穴端点；侧视切边竖直。
- 兽耳与发夹归属由项目确定。示例中兽耳归后发，唯一发夹归角色左侧刘海，不把示例选择当作所有角色的固定规则。
- 简化头发时保留总轮廓、长度与流向，用少量连通宽厚体块、浅沟槽和圆钝末端，减少细丝与深缝；体块数量按角色复杂度调整。
- 去眼部阴影与保留虹膜高光是独立约束。取消眼白灰带与眼窝暗缝时，保留小白色高光、原眼距与表情，使眼缘贴合脸部。
- T-pose与A-pose按最新确认选择，不混用。T-pose侧视沿手臂轴线看到袖口与指尖，远侧手臂被遮挡，不能把手画成竖起的手掌。
- 腿部严格侧视允许远侧腿和鞋被遮挡，不错开腿来显示两条腿。鞋头细节不能粘贴到后视鞋跟。
- 领口、围巾、头发空腔、裙内连接段与袖口通道保持同一角色比例。绘制接口参考不等于已证明实际模型没有穿模。

### 画幅与尺度

主体70–85%用主要尺寸占比表达，不理解为必须占画布面积70–85%。同一模块的各视图保持相同尺度和关键标高。横向T-pose模块可依用户已确认偏好使用宽正后视与窄侧视，不通过拉伸或随意放大某一视图满足构图。

各模块独立放大成图后，总图高度不是统一角色尺度。用整角色比例和接口标记比较不同模块，不按各自图像总高直接拼接。报告实际原生与导出尺寸，放大图不冒充原生高分辨率。

保存独立PNG、优化提示词、接口说明与版本清单。保留已确认版本，单项修复另存新版；最终交付只指向最新确认文件，不混入已弃用的眼部或服装版本。

### 检查与交付

使用 [references/quality-checks.md](references/quality-checks.md) 的“阶段一”检查本轮图像。说明输出路径、视角、画幅、实际尺寸、使用的提示词和存在的细微视图误差。多张AI生成图不能保证严格共用同一几何；不要承诺像素或几何完全一致。

提示词明确标注现阶段为设定图参考，不宣称已完成三维模型、拓扑、绑定或零穿模。

## 阶段二：模型 UV 重排与贴图处理

把 AI 模型上成千上万的碎 UV 岛，重排成按部位划分、人能看懂和绘制的大块面板。原贴图无损迁移过去，再按需清理和修正，最后打包交付。工具是 `scripts/origami_uv/run.py` 加项目里的 `config.yaml`，全流程可以重跑。

1. **确认输入与环境**（[uv-relayout.md](references/uv-relayout.md) 的“输入要求”和“环境”）：
   - 每个模块一个三角网格对象，原 UV 层名，原贴图位置；
   - 有没有骨架，坐标朝向和单位；
   - Blender 路径和 Python 依赖。

   从 `config.example.yaml` 复制一份 config，填好上面这些。
2. **先跑 0–3 看排布**：看图集总览和部位色块表。不满意就调整，然后 `--from-stage 2` 或 `--from-stage 3` 重跑：
   - 分区规则：先用 `generic`，不合适的部件再写专用规则；
   - 打包组顺序、合并、间距、旋转。
3. **跑 4–8**：迁移、导出、对比图、报告和交付包。
4. **贴图清理（可选，按 [texture-processing.md](references/texture-processing.md)）**：用户想用图像模型去脏色、烘焙阴影或涂抹时：
   1. 用 `--texfix-prepare` 切出裁块，为每块写针对性的提示词；
   2. 在用户自己的 ChatGPT 等服务里逐块生成。每次发送前确认附件、模式和提示词；发送需要用户同意。
   3. 结果按块名放回 `gpt_results/`，然后 `--from-stage 4`。

   脸和眼睛默认不送。
5. **定点修正**：用户指出的具体问题（例如“这条纹其实是阴影”“这块白色是大腿皮肤”）写成 `touchup` 条目。归属不确定时先问。改完用近景渲染核对，背面和接缝也要看；现有操作不够用时，在 `touchup.py` 里加新操作。
6. **验收与交付**：
   - 按 [quality-checks.md](references/quality-checks.md) 的“阶段二”检查 `report.md` 和 `metrics.json`；
   - 交付包里说明残留问题和未达标项，并说明原因；
   - 清理前的迁移贴图保留着，可以随时换回。

原则：
- 输入 blend 只读；顶点、面、权重、原 UV、自定义法线都不改，导出后回读核对。
- 以近景渲染判断贴图质量，不只看数字。
- 每个修改都写进 config 或代码，保证重跑结果一致。
- 资源：展开和打包时每个进程约需 1 GB 内存。C 盘满了会让页面文件无法增长，导致崩溃，长任务开始前先检查。

## 阶段三：导入 UE5 做成可操控角色

按 [ue-playable-character.md](references/ue-playable-character.md) 操作，脚本在 `scripts/ue_character/`。

1. **确认环境**：
   - UE 项目路径和引擎版本，项目里有没有第三人称模板内容（没有就从引擎模板复制，复制前确认不会覆盖已有文件夹）；
   - 编辑器是否已关闭，内存和显存是否够用（大型游戏开着时会失败）。
2. **写 `ue_config.json`**：交付包路径、部件名、双面部件、胶囊尺寸、模型朝向、只需对齐的骨骼（默认手臂）。
3. **构建**：删除上一次生成的内容目录及其 `__ExternalActors__`/`__ExternalObjects__` 子目录（只删脚本生成的），再以 `-ExecutePythonScript … -nullrhi` 运行 `ue_build_playable.py`。
4. **实机测试**：
   1. 用 `-ExecCmds="py …"` 运行 `ue_verify_play.py`（会弹出编辑器窗口，先告诉用户）；
   2. 用 `make_preview_sheet.py` 生成预览表；
   3. `checks` 必须全部通过，并且要看过预览表；
   4. 姿势不对时用 `ue_diag_pose.py` 判断是重定向器的问题还是动画蓝图的问题。
5. **交付说明**：打开哪个关卡、点 Play、操作键；限制（手指、次级骨骼没有物理、脚部 IK 已关闭、材质不是卡通着色），以及可做的后续。

原则：不改项目的默认地图、GameMode 等全局设置；不动用户已有的角色和关卡；生成的内容都放在单独的内容目录里。
